# AI 综合卦象解读设计

## 目标

在所有占问类型的 AI 深解中增加“综合卦象解读”，稳定呈现卦局基础、体用与问题核心、变卦整体走势和综合结论，并根据风险类型输出相应现实边界。

## 输出结构

新增 `comprehensive_hexagram_reading` 对象：

- `foundation_summary`：概括本卦、互卦、变卦、体卦、用卦、五行关系和旺衰。
- `foundation_points`：逐条解释本卦、互卦和变卦在当前问题中的含义。
- `core_summary`：说明体用关系如何对应所问之事的核心矛盾。
- `strengths`：当前有利条件或可利用力量。
- `weaknesses`：当前不足、消耗或限制。
- `key_risks`：最需要防范的失误、阻碍和现实风险。
- `trend_summary`：以变卦为主描述发展走势，不虚构具体日期或保证结果。
- `trend_branches`：给出条件化的发展分支。
- `conclusions`：三至五条直接、具体、紧扣问题的综合结论。
- `disclaimer`：按普通、体育、医疗、法律、投资或紧急风险生成现实边界提示。

## 页面结构

AI 深解完成后，将“综合卦象解读”放在现有 AI 内容顶部，并按以下顺序渲染：

1. 一、卦局基础
2. 二、体用与问题核心
3. 三、变卦整体走势
4. 四、综合结论
5. 温馨提示

各部分使用段落和有序或无序列表，不依赖模型生成 Markdown 标记。已有旧记录没有新字段时继续显示原有 AI 深解，不报错、不显示空卡片。

## 内容规则

- 必须引用服务端提供的本卦、互卦、变卦、动爻、体用、五行和旺衰，不得改写排盘事实。
- 所有结论必须与用户具体问题建立联系，不能仅输出通用易学释义。
- 每一卦都要解释“该卦在当前问题里具体对应什么”，不能只写“主变化、宜谨慎、循序渐进”等抽象套话。
- 体用部分固定拆分为有利条件、不足限制和关键隐患，并说明这些因素分别对应现实中的谁、什么条件或什么行为。
- 走势部分必须给出至少两个条件化分支，例如“若先完成某项现实条件，则……；若继续维持当前做法，则……”。
- 综合结论必须给出三至五条可单独阅读的直接判断，明确回答宜、不宜、主要风险、优先动作和复核信号。
- 根据提问语境动态理解“问题核心”：体育为胜负核心，感情为关系核心，事业为事业核心，求财为财运核心，出行办事为成事核心，但页面统一使用“体用与问题核心”以兼容所有类型。
- 使用条件性表达，不提供虚构概率、比分、日期、金额或保证性结论。
- 体育问题可描述相持、节奏、胜负倾向和分差形态，但不得鼓励投注。
- 高风险专业问题继续由现实专业建议覆盖普通卦象判断；紧急人身安全问题停止预测。

## 详细度与语言风格

- 整体详细度参考“巽为风变风山渐”的赛事解读示例，但只借鉴层次和具体程度，不复制赛事结论。
- 术语后立即附白话解释，并继续说明它与用户问题的直接关系。
- `foundation_points` 至少覆盖本卦、互卦和变卦三个角度；不得把三卦合并成一句空泛总结。
- `strengths`、`weaknesses`、`key_risks` 和 `trend_branches` 各自至少提供一条实质内容。
- 结论不能重复前文原句，要把卦象信息压缩成用户可以理解和执行的判断。
- 普通问题不得虚构具体成功率；体育问题不得虚构精确概率、确定比分、球员伤病或稳赚投注建议。
- 温馨提示必须针对问题类型生成，不得所有问题都使用同一句免责声明。

## 兼容性

- 保留现有 `hexagram_synthesis` 等字段，避免破坏管理页、旧数据和已有测试。
- 新字段进入严格 JSON Schema 的 `required` 列表，只影响新生成或重新生成的 AI 深解。
- 前端对缺失的新字段做兼容判断。
