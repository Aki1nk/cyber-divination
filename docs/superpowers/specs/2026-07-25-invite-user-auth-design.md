# 邀请码用户认证设计

## 目标
为全站增加普通用户登录：大陆手机号 + 密码，注册必须消耗管理员后台创建的一次性邀请码；登录、注册、隐私页和管理员后台之外均需用户会话。

## 已确认规则
- 手机号为唯一 11 位大陆号码；昵称可选。
- 密码 8–64 位，拒绝常见弱密码；管理员可下发临时密码，用户登录后必须修改。
- 邀请码 4–64 位，仅中文、字母、数字，字母不区分大小写；可选过期时间，可作废，只能使用一次。
- 会话 30 天、多设备；5 次失败后按手机号和 IP 暂停 15 分钟。
- 用户可改密、退出当前设备、验证密码后注销；手机号仅管理员可改。
- 管理员可管理用户、备注、状态、临时密码和邀请码。
- 新卦象关联账户；旧本机历史不自动认领，云端仍保留 30 天。

## 技术设计
- D1 新增 `users`、`user_sessions`、`invite_codes`、`login_attempts`，并给 `readings` 增加可空 `user_id`。
- 密码使用 PBKDF2-HMAC-SHA256、独立随机盐和版本化参数；会话使用随机令牌，D1 只存 SHA-256 哈希。
- Cookie 使用 `HttpOnly; Secure; SameSite=Strict`，普通用户与现有管理员会话完全分离。
- 邀请码保存规范化 HMAC 查找值和 AES-GCM 密文；密钥来自 `INVITE_CODE_ENCRYPTION_KEY` Secret，原码不明文落库。
- 注册依次验证邀请码、创建用户、核销邀请码和创建会话；仓储使用 D1 batch 保证原子提交。
- 登录错误统一，认证响应禁用缓存；用户禁用、注销或会话到期后立即失效。

## 界面与接口
- SPA 新增登录/注册双标签页和账户中心；启动先请求 `/api/auth/session`，未登录或强制改密时执行路由门禁。
- 新增 `/api/auth/register`、`/login`、`/session`、`/password`、`/account`。
- 后台新增用户和邀请码页及对应 `/api/admin/users`、`/api/admin/invites` 接口。
- 卦象创建和重试改按 `user_id` 授权，设备编号只保留幂等与诊断用途。

## 发布
先执行 D1 迁移并设置 `INVITE_CODE_ENCRYPTION_KEY`，再部署登录门禁代码；上线后管理员创建首个邀请码并完成注册、登录、起卦、改密、注销冒烟测试。
