# 结合问题的本地详细解读 v2 设计

**日期：** 2026-07-25

**状态：** 已批准

**范围：** 本地问题解析、现代卦象主题、宜/不宜判断、详细解读结构、版本兼容与自动化测试。起卦和排盘算法不变。

## 1. 目标

将当前主要依据体用和旺衰生成的通用解读，升级为能够结合用户问题、可明确回答“宜/不宜”、内容具体且可执行的本地确定性解读。

新版必须同时满足：

- 问题和背景仅在本机处理，不调用 AI、后端或网络服务。
- 解读明确对应用户所问事项，而不是只复述卦名和体用关系。
- 结论可以使用“宜、暂不宜、宜先……再……”等直接表达，但不得承诺必然结果。
- 每项结论都能通过规则键追溯到问题特征、卦象主题、体用、旺衰或动爻阶段。
- 经典原文、现代解释和现实安全边界继续严格分层。

## 2. 不在范围内

- 不修改数字、时间、随机取象或外应取象的成卦规则。
- 不修改本卦、互卦、变卦、动爻、体用或五行旺衰计算。
- 不调用大语言模型，也不要求 API 密钥、账号、云同步或远程数据库。
- 不对问题中未出现的人物、金额、期限、承诺或结果进行推断。
- 不把宜/不宜表达包装为医疗、法律、投资或重大人生决定的专业意见。

## 3. 总体数据流

起卦控制器在卦象生成后执行以下纯本地步骤：

1. 使用用户确认的问题、类别和可选背景生成 `questionContext`。
2. 从本卦、互卦和变卦读取对应的现代主题资料。
3. 根据体用关系生成基础宜/不宜判断。
4. 使用体势、用势和动爻阶段调整行动力度与顺序。
5. 根据问题意图和关注点，将卦象规则改写为对应事项的九段式解读。
6. 保存问题解析快照、解读版本和全部 `reasonKeys`。

问题解析只能影响解释文字，不能写回或改变排盘数据。

## 4. 本地问题解析

新增纯函数 `analyzeQuestion({ question, background, category })`，返回冻结对象：

```js
{
  category: 'career',
  intent: 'action_planning',
  focuses: ['timing', 'collaboration'],
  subjects: ['项目', '团队'],
  timeSignals: ['近期'],
  confidence: 'matched',
  reasonKeys: [
    'category:career',
    'intent:action_planning',
    'focus:timing',
    'focus:collaboration'
  ]
}
```

### 4.1 意图分类

- `decision`：要不要、是否、能否、适不适合。
- `action_planning`：怎么、如何、先做什么、怎样推进。
- `timing`：什么时候、近期、下周、现在是否合适。
- `relationship`：沟通、合作、复合、对方态度、人际边界。
- `comparison`：两个或多个选择之间如何取舍。
- `general`：无法可靠匹配时的保守退化类型。

### 4.2 关注点分类

确定性词典识别资源、成本、时间、协作、阻碍、结果、风险、学习、出行等关注点。一个问题可以命中多个关注点，但按固定优先级去重，输出顺序保持稳定。

### 4.3 主体和时间信号

主体只从有限、明确的名词词典中提取，例如项目、工作、团队、对方、考试、申请、行程。时间信号只保留用户原文中的近期、下周、今年或明确日期，不把它换算成预测日期。

### 4.4 冲突与退化

- 用户选择的类别优先于关键词推断，关键词只补充意图和关注点。
- 多个意图同时命中时，比较意图优先；“如何、怎么、安排”等强行动词优先识别为行动规划；“什么时候、何时、现在是否适合”等明确时机问法识别为时机意图；“近期、下周、今年”等普通时间词只作为时间关注点和时间信号，不单独覆盖行动规划或决策意图。
- 无可靠主体时统一使用“所问之事”，不虚构名称。
- 无可靠意图时依据用户选择的类别输出通用但仍对应问题原文的解读。

## 5. 现代卦象主题资料

新增本地 `HEXAGRAM_GUIDANCE` 数据表，为 64 卦分别提供现代解释层资料：

```js
{
  situation: '当前局势的结构性主题',
  process: '处理中间环节时应留意什么',
  tendency: '完成必要调整后的发展倾向',
  favorable: ['可以借助的条件'],
  cautions: ['需要避免的做法'],
  actions: ['适合采取的现实行动'],
  sourceKeys: ['modern_guidance:12']
}
```

- 本卦使用 `situation` 描述当前结构。
- 互卦使用 `process` 描述中间变化和隐含环节。
- 变卦使用 `tendency` 描述调整后的后续倾向。
- 现代主题必须标注为应用编写的规则解释，不能冒充卦辞、象辞或爻辞原文。
- 64 卦必须全部覆盖；缺少记录时使用明确的保守退化文案，不能静默生成空内容。

## 6. 宜/不宜判断矩阵

基础判断由体用关系确定：

| 体用关系 | 基础判断 | 行动力度 |
| --- | --- | --- |
| 体克用 | 宜主动推进 | 先处理可控部分，避免操之过急 |
| 用生体 | 宜借力推进 | 先确认外部资源真实可用 |
| 体用比和 | 宜稳步推进 | 保持节奏并确认共识 |
| 体生用 | 宜控制投入后推进 | 先设成本、时间和承诺上限 |
| 用克体 | 暂不宜强行推进 | 先降低风险、补条件或等待变化 |

体势用于调整结论：

- `prosperous`：可以推进关键步骤，但仍需现实核验。
- `supported`：宜借助已确认的人员、资源或基础。
- `resting`：宜准备、观察或小范围试行。
- `weakened`：暂不宜扩大投入，先保留余量。

用势强时增加外部依赖、沟通和协商检查。动爻位置只作为解释层阶段提示：初、二爻为早期，三、四爻为中段，五、上爻为后段；该映射必须标注为应用的阶段规则，不宣称是具体时间预测。

高风险问题优先显示现实边界，并覆盖普通宜/不宜行动建议。

## 7. 九段式详细解读

新版 `interpretation.sections` 固定按以下顺序输出：

1. `verdict` — **宜 / 不宜结论**：一句直接结论，例如“宜先准备后推进，暂不宜立即定案”。
2. `direct_answer` — **直接回答**：明确说明该判断如何对应用户问题与意图。
3. `current_situation` — **当前局势**：结合问题和本卦现代主题。
4. `development_process` — **发展过程**：结合问题和互卦现代主题。
5. `future_tendency` — **后续倾向**：结合问题和变卦现代主题，使用非保证性措辞。
6. `favorable` — **有利条件**：结合体用、体势和问题关注点说明可以借助什么。
7. `obstacles` — **主要阻碍**：结合用势、问题关注点和卦象提醒说明容易卡在哪里。
8. `action_order` — **行动次序**：固定输出第一步、第二步、第三步，每一步必须可执行、可验证。
9. `avoid_and_verify` — **暂不宜做与验证标准**：说明暂时避免什么，以及满足哪些现实条件后再推进。

各段必须携带非空 `reasonKeys`。结果页继续按已有通用 section 渲染机制显示卡片，不新增网络状态或 AI 按钮。

## 8. 类别化表达

同一卦象规则根据问题类别转换为不同的现实对象：

- 事业：资源、负责人、职责、进度、合同、协作依赖。
- 感情与人际：沟通、边界、回应、信任、双方意愿。
- 学业：知识基础、复习节奏、材料准备、反馈与申请条件。
- 行程计划：时间、路线、证件、天气替代方案和同行协调。
- 其他：使用中性的条件、资源、步骤和反馈表达。

类别化只改变表述对象，不改变卦象判断结果。

## 9. 版本与历史兼容

- 新生成结果使用 `profileId: 'local-deterministic-v2'`。
- v2 保存 `questionContext` 和九段式 `sections`。
- 已保存的 v1 卦例保持原样展示，不重新计算或覆盖。
- 记录结构继续由仓库版本化保存；读取旧记录时不要求存在 `questionContext`。
- 同一问题 24 小时内命中旧记录时仍返回当时不可变的原结果，不强制升级到 v2。

## 10. 安全与措辞边界

- 允许明确使用“宜、暂不宜、宜先……再……”。
- 禁止“必然、注定、一定成功、一定失败、稳赚、治愈、必有灾祸”等保证或恐吓措辞。
- 医疗、怀孕、生死、法律、犯罪、投资、大额资金和自伤风险继续执行现有边界。
- 自伤或紧急危险内容优先给出现实求助建议，不继续输出宿命式吉凶分析。
- 问题和背景进入 HTML 前继续使用现有安全转义，不允许用户输入形成标签或脚本。

## 11. 测试与验收

自动化测试至少覆盖：

1. 不同说法能够稳定匹配决策、行动规划、时机、关系和比较意图。
2. 类别选择优先，未知问题稳定退化为 `general`。
3. 64 卦现代主题完整、唯一且字段齐全。
4. 五种体用关系生成正确的宜/不宜基础判断。
5. 四种体势和强用势能够正确调整行动力度。
6. 六个动爻位置映射到早期、中段、后段且不生成具体日期。
7. 九个 section 顺序稳定、文本非空、`reasonKeys` 非空。
8. 解读文本引用问题主体或安全退化词“所问之事”。
9. 高风险建议覆盖普通行动建议。
10. v1 历史记录继续渲染，v2 新记录保存问题解析快照。
11. 全局禁用确定性承诺措辞。
12. 桌面与 390px 结果页无横向溢出，九段内容可读，四个标签页仍可操作。

## 12. 验收示例

问题：“如何安排项目的下一阶段工作顺序？”

示例结果：

> **宜先准备后推进，暂不宜立即定案。**
>
> 你问的是项目下一阶段的行动顺序。用生体表示外部条件可以提供帮助，体势当令表示当前具备一定执行基础；但动爻处于早期阶段，宜先确认负责人、依赖事项和完成标准，再进入集中执行。
>
> **第一步：** 列出必须由外部团队确认的依赖事项。
>
> **第二步：** 用一个小范围任务验证资源和协作是否到位。
>
> **第三步：** 验证通过后再确定完整时间表。
>
> **暂不宜：** 在关键负责人和依赖条件未确认前一次性承诺全部进度。

该示例仅展示结构；实际文字必须由问题解析、64 卦主题、体用、旺衰和动爻规则共同确定。
